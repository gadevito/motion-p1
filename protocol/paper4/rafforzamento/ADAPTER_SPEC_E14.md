## 0. Schema (P4R §6, as signed): S0 and S1

**S0** = observed sites' **factor history** (the only dynamic reading), calendar, topology, explicit masks. No flow, no occupancy, no historical average, no coordinates, no target-specific embeddings. **S1** = S0 + coordinates with a shared encoding. The dynamic benefit of P4R is therefore the benefit of the factor history of the observed sites and of nothing else. (Draft 2 of E14 had added flow and occupancy: withdrawn.)

## 1. Tensors, per batch of B origins, N nodes (all nodes of the city, hidden included), T_IN = 12 input steps, H = 8 decoder steps

| Symbol | Shape | Content | Source |
| --- | --- | --- | --- |
| `r_in` | (B, T, N, 1) | factor r of the **input nodes** at steps t−11…t, **standardised** (§4); 0 where the node is not an input node or the reading is missing | `Setup.Rf`-equivalent from the factor series; input set = `inp` of `batch_mask` (training) or observed nodes (validation, test) |
| `m_in` | (B, T, N, 1) | **input-availability mask**: 1 if the node is an input node **and** the reading at that step is valid; else 0 | masks and validity of the series |
| `node_in` | (N,) | 1 if the node is an input node of the batch (admitted as input), else 0; constant over steps | `inp` |
| `cal_in` | (B, T, N, 5) | the five calendar channels of `p4b` (sin/cos of time of day, sin/cos of weekday, weekend flag) at steps t−11…t, identical for every node | timestamps |
| `cal_out` | (B, H, N, 5) | the same channels at steps t+1…t+8 | timestamps (known in advance) |
| `xy` | (N, 2) | UTM coordinates standardised on the observed-training sites (S1 only) | sensor registry |
| `A` | (N, N) | the method's graph (§6), fixed per city | aligned road graph |
| `y` | (B, H, N, 1) | factor r at steps t+1…t+8, standardised (for the loss) and raw (for the metrics); NaN where missing | factor series |
| `m_y` | (B, H, N, 1) | **target mask**: 1 for the target nodes of the batch (masked observed cells in training; validation-hidden or test-hidden at evaluation) with a valid target; else 0 | masks, validity |

Three distinct notions, never merged: **node admitted as input** (`node_in`), **reading missing at a step** (`m_in` = 0 while `node_in` = 1), **node to complete** (`node_in` = 0: masked observed cell or hidden node). In the original all three collapse into "value 0" (audit §4); here they are explicit.

Hidden nodes (validation- and test-hidden): `node_in` = 0 in every batch, `r_in` = 0, `m_in` = 0; their own readings never enter any tensor of the input side, nor the scalers (§4), nor the graph weights (§6). They are target nodes only in the authorised selection (validation-hidden) and in the final evaluation (test-hidden).

## 2. Input completion by the mixture of graph experts (DataPreparation) **[original mechanism, mask-driven]**

Original: `x_enc` (B, T, N, 1) is squeezed to (B, N, T); nodes with zero sum over the batch are "unknown"; the sparse gating (Linear T→64→E, top-k = 3 of 5) weights the experts' completions computed on `adj` without self-loops with the unknown columns masked; every value equal to 0 is replaced by the combined completion (`miss_ix = (x_enc == 0)`).

Adapter: the experts receive **the factor channel only**, (B, N, T) = `r_in` squeezed — exactly as the original (the experts and the gating are single-channel; audit and code). **[adaptation]** `batch_unknown_nodes` = the nodes with `node_in` = 0 (from the mask, not from the batch sum); the replacement index `miss_ix` = (1 − `m_in`) (missing readings and non-input nodes), not `(x == 0)`, so that a valid standardised value exactly equal to 0 is never replaced and a non-input node is always completed. The experts' aggregation conventions (mean, weighted mean, diffusion from the row; maximum and minimum from the column, a masked node receiving 0 there; non-neighbours contributing 0 in max/min) are **kept as in the code** and recorded (audit §5): a correction would be a variant of the method.

Output of the completion: `r_c` (B, T, N, 1), the completed factor.

## 3. Encoder and decoder **[original architecture; exogenous channels added as a declared adaptation]**

The original `Seq2Seq(enc_in = 1, d_model = 64, e_layers = 2, out_len, k_hop = 1)`: `Seq2Seq` passes the same `num_layers` to `Encoder` and `Decoder` (`MoGERNN.py`, `Seq2Seq.__init__`), so **two `DCRNNCell` layers in the encoder and two in the decoder** (`d_layers` of `args.py` is not used by the model), `fc: 64 → 1`; each gate is a `DiffConv` on `[input ; hidden]` with supports A_q = D⁻¹A (forward random walk) and A_h = D⁻¹Aᵀ, order k = 1 → three matrices (I, A_q, A_h): **one hop per support per recurrent step**. The decoder's first input is the last completed input step `x_enc[:, −1]` (B, N, 1) — **the completed value**, which for a non-input node is the experts' reconstruction, not an observed value; at each further step the input is the previous output (`fc(h)`), or the target when teacher forcing is drawn.

**[adaptation] Entry point of calendar, mask and coordinates.** The original has none (`t_mark`/`pos_mark` are accepted by `Model.forward` and ignored by `DataPreparation` and `Seq2Seq`). The adapter concatenates them as **exogenous input channels of the recurrent cells**, encoder and decoder alike:

- encoder input at step t: `[r_c(t) ; m_in(t) ; cal_in(t)]` (+ `xy` in S1) → `enc_in` = 1 + 1 + 5 (+ 2) = 7 (S0) or 9 (S1); the first encoder cell `DCRNNCell(enc_in, 64)` is the original cell with a wider input; hidden size, number of layers (2 + 2), k_hop unchanged;
- decoder input at step h: `[ŷ(h−1) ; node_in ; cal_out(h)]` (+ `xy` in S1), where `ŷ(0)` = `r_c(t)` (the completed last input, as in the original) and `ŷ(h−1)` = `fc(h_{h−1})` the previous output — **the autoregressive recurrence on the factor is kept**; `fc: 64 → 1` outputs the standardised factor; the mask channel of the decoder is the constant `node_in` (there is no per-step availability in the future); **teacher forcing disabled** (ratio 0 in every arm, every epoch; P4R §5).

The parameter count therefore differs from the original's 226 270 (which belongs to the original configuration); the adapter's count is recorded by the preflight.

**Dynamic suppression (S0-nodyn, S1-nodyn) [adaptation]:** **`r_in` ≡ 0** for every node and step; **`m_in`, `node_in`** and every other tensor (`cal_in`, `cal_out`, `xy`, `A`, `y`, `m_y`) **identical** to the corresponding full cell, so that the availability information and the points where the completion intervenes are the same in the two arms and the contrast concerns the factor history only. The experts operate on the zeroed input with the same masks; no assumption is made that their output is a constant (learned biases and availability patterns may produce values varying along the window). C0.3 asserts the equality of every tensor except `r_in` between the two cells of a pair.

## 4. Scalers **[adaptation: admissible statistics]**

Factor scaler per split: mean and standard deviation of the **valid** factor values of the **observed nodes over the training period** (`reg_end`), computed once per (city, seed), identical in the four cell types; standard deviation floored at 1e-6; `r_in` and `y` standardised with it; **inversion before MAE/RMSE**, which are computed in factor units. (`p4b.Setup._stats` standardises flow and occupancy, not r: the factor scaler is the adapter's own, recorded in the fingerprints.) Missing readings: NaN in the series → 0 after standardisation with `m_in` = 0 (the original sets NaN to 0 after scaling; the meaning "0 = mean" is the same, but here the mask carries the information). The original's inclusion of the new sensors' history in the test-time statistics (audit §1) does not exist: the statistics are frozen at training.

## 5. Loss, targets, selection

**Training loss [original form, adapted targets]:** MSE on standardised values (original default `--loss mse`), over the **target entries only**: `m_y` = 1, i.e. the masked observed cells of the batch with a valid target, all **8 decoder steps** (the original supervises every prediction step; the four P4R horizons 1, 2, 4, 8 are read for the metrics, the other steps are supervised but not evaluated). Input nodes' own values are never targets (the original trained on every known node's targets). Hidden nodes never in the loss.

**Selection:** validation MAE in factor units on the validation-hidden nodes, mean over the four horizons, at checkpoints every 500 updates; best checkpoint per configuration; configuration chosen per split as E13B (adequacy rule, extension, lock unchanged).

**Optimiser and grid [reference = the original training script]:** C1 — AdamW, lr 1e-3, weight decay 1e-4, **no scheduler** (the original training script disables it), batch 32, one update per batch; C2 — lr 3e-4, otherwise C1; C3 — C1 with ReduceLROnPlateau, a **declared adaptation** with a fixed policy: the scheduler steps once after each validation checkpoint (every 500 updates in development and final; never at checkpoint 0; order at a checkpoint: evaluate → scheduler step on the validation MAE → save), factor 0.5, patience 1 checkpoint, min lr 1e-5; C3 runs only in development/final, so the cadences of C0.2 (250) and of the benchmark (10) never involve the scheduler; C4 — C1 with weight decay 0. **Reduced grid, if the budget rule applies: C1 and C2** (the reference and the lower learning rate). **No dropout anywhere** (the original model has none; a dropout would be an architectural addition). Gradient clipping: none (not in the original). Seeds: E9 streams for masks and batches, development stream 7 and final stream 6 for the initialisation.

## 6. Graph **[the method's own construction, on the E11 aligned graph]**

Paper Eq. 1 and the loaders: a Gaussian kernel on **road-network distance** between sensor pairs, `A_ij = exp(−(d_ij/σ)²)`; d_ij = shortest-path length on the aligned road graph between the kept sensors (travel distance, metres). **Declared adaptation — a common road radius R = 2 000 m, applied before σ is estimated:** pairs farther than R along the road network are treated as not connected (d_ij = ∞), the same rule in the three cities. The reason is to keep the exchanges local to road connections: on our aligned graphs every pair has a finite distance, and without a radius σ is dominated by the far pairs (1.5–10 km) and the graph is dense (density 0.39–0.44, median degree ~300 — the topological diagnostic of 2026-11-24, before any fit, is in the decision note `DECISION_20261124_E14_GRAPH_RADIUS.md` with the alternatives examined: no radius, 3 km, 1 km, 500 m, a per-city radius). R is **our choice**, not a documented constant of the reference method: DCRNN's `gen_adj_mx.py` initialises the distances to ∞, fills in the pairs present in its distance file and takes σ on the finite ones — we keep that Gaussian transformation; we do not claim that its missing pairs were excluded by a radius. Then σ = standard deviation of the finite d_ij (diagonal zeros included); threshold κ: entries with A_ij < 0.1 set to 0, so the effective radius is σ·√ln 10 ≤ R (σ, the effective radius and the longest surviving edge are logged per city in the preflight); diagonal: the experts remove self-loops themselves (`adj_noselfloop`), the random walk keeps whatever the matrix has — the adapter passes **A with zero diagonal** and lets the code behave as on the original data. Isolated nodes (degree 0, expected in Melbourne, whose sensors are sparser): the random walk sets d = 1 (original `calculate_random_walk_matrix`) and the experts aggregate nothing from neighbours — their output is not necessarily zero (the transformations after the aggregation carry biases and learned parameters); such a hidden node receives **no dynamic reading from the observed nodes** and can still use the calendar, the coordinates in S1 and the learned parameters; it is *dependency excluded* in C0.5(a), a consequence reported per city, not an aim of the choice. The random walk is recomputed at each forward on CPU in the original; the adapter **caches** A_q and A_h once per city (authorised optimisation; bit-identical result asserted in the preflight). The graph is the same in every cell type and is built from topology and coordinates only (no reading).

**Dependency and sensitivity (C0.5), two distinct measures.** (a) **Structural dependency**, derived from the architecture by propagating **boolean dependencies** through the operations of the adapter: a dependency matrix D (targets × input nodes) is built by composing the structural supports of every operation in the order of the forward pass — the experts' completion (support of `adj_noselfloop`, union over experts: rows for mean / weighted mean / diffusion-A_q, columns for max / min / diffusion-A_h; the identity for input nodes; the completion support given **only to the nodes where `m_in` = 0 somewhere in the period**: non-input nodes, and input nodes with a missing reading, so that an input node with complete readings depends on itself alone), then, for each recurrent step and layer, each gate's `DiffConv` (support S = I ∪ A_q ∪ A_h): at a layer's **first** recurrent step the hidden state is identically zero, so r·h ≡ 0 and u·h ≡ 0 and the new state depends on S·(inputs) — **one hop**; afterwards the reset gate multiplies a non-zero state before the candidate and two convolutions compose, deps(h') = S²·(deps x ∪ deps h) — **two hops**; the layer stacking; the decoder steps with the output re-entering as input; D_h for horizon h is this composition on the 0/1 patterns only (no weights, no activations). It is an **upper bound** of the information path of the architecture: a target with an empty row in D_h cannot depend on any input node's readings; a non-empty row does **not** demonstrate a dependence. The earlier hop count was wrong because it ignored the composition inside the cell and across layers; a bound does exist and this is how it is derived. Reported per (city, seed) and horizon, with the bound's nature stated: the share of validation-hidden, test-hidden and sampled training targets (20 masks) with a non-empty row (*dependency possible*) and the row sizes, the completion support taken with the missing readings of the validation, test and training period respectively; the hop distance to the nearest input node on `A ∪ Aᵀ`, with the shares within the declared radii of 14 and 21 hops, as descriptive measures. **This is computed in the deterministic preflight, before the signature, on all 15 (city, seed), without any trained state.** (b) **Local numerical sensitivity**, after the tag and only where a trained state exists: on the C0.2 realisations (Madrid seed 0), for the S0-full arm at its best checkpoint of the dependent condition and at the stream-7 initialisation, the gradient of each decoder output with respect to each input node's series (float64, CPU), reported as the share of hidden targets with |gradient| > 10⁻¹² and its distribution — a property of weights, activations and inputs, **not** a reachability classification: a sub-threshold gradient does not make a node structurally unreachable. The **reference linear operator** of the diagnostic, Σ_{k≤14}(A_q)^k, is declared as such in C0.2 and is not identified with the model's propagation.

## 7. C0.2 — synthetic regression control, fully specified

Realisations: `e13.synth_processes(su, kind, seed)` with seeds **20261121 (dependent)**, **20261122 (independent)**, Madrid seed 0; the continuous target is the latent factor **z** returned by the generator (not its classes), injected as the factor series; flow and occupancy are not used by S0. Both realisations are validated **before the first fit** with the following diagnostic, then two cells are trained (S0-full, S0-nodyn) per realisation: **four trainings of 2 000 updates**.

**Diagnostic (privileged, as `e13.tabular_diagnostic`; MAE version).** Tables fitted on training origins and read on validation origins, on the validation-hidden nodes — privileged: the tables use the hidden nodes' own historical values, which the model never sees. Table A (calendar): for each weekly slot s (weekday × 15-min slot, 672 slots) the **median** of z over the validation-hidden nodes' training-origin targets at horizon h with target slot s (fallback: the global median over all slots if a slot has fewer than 5 values). Table B (calendar + neighbourhood): the median of the same targets within (slot s) × (bin of the spatial feature), where the spatial feature is the input nodes' z at the origin propagated by the **declared reference operator** Σ_{k≤14}(A_q)^k (a linear reference on the method's graph, not the model's propagation) and divided by the propagated mass (0, in its own bin, where no input node is reachable), binned in 32 equal-width bins over [0, 1.6] plus the unreachable bin (fallback to Table A's slot median when a (slot, bin) has fewer than 5 values). MAE_A and MAE_B on the validation origins per horizon; gain_h = 100·(MAE_A − MAE_B)/MAE_A; the diagnostic gain is the **mean over the four horizons of gain_h**. Validity: dependent **≥ 10 %**, independent **within ±1 %**; thresholds fixed now, before the realisations exist; a realisation outside them is recorded as invalid and nothing is trained.

**Training control:** S0-full and S0-nodyn, configuration C1, 2 000 updates, validation MAE (factor units) every 250 on the validation-hidden nodes; best checkpoint = checkpoint ≥ 500 with minimal validation MAE of S0-full (MAE in factor units, mean over the four horizons); **V at that checkpoint = the mean over the four horizons of the per-horizon ratios** 100·(MAE_nodyn,h − MAE_full,h)/MAE_nodyn,h — the same aggregation as the primary contrasts, not the ratio of mean MAEs. Dependent **passes if V ≥ +3 %** (no acceptance route); independent **anomaly if V > +3 % at any checkpoint ≥ 500** (dated note and bounded acceptance), reported if V < −3 % at some checkpoint.

## 8. Counts and preflight checks

C0.1 hidden-node invariance: **8 trajectories of 50 updates** (four cell types × original/perturbed), compared per cell type bit for bit (losses, parameters, validation predictions). C0.2: **4 trainings of 2 000**. E14-pre benchmark: four cell types × 3 repetitions × 60 updates (720 updates) on Spark, seconds per update as (t₆₀ − t₁₀ − Σ of the five validation passes between them)/50, **net of the validation passes** (the gross value recorded, not used), median; seconds per validation as the median duration of a validation pass; memory peak recorded; the three identical repetitions compared (determinism observation).

Deterministic preflight (no update): equivalence of the adapter with the original on the original configuration (enc_in = 1, no exogenous channels, teacher forcing as in the code, `miss_ix = (x == 0)`, `batch_unknown_nodes` from the batch sum): forward identical within 1e-6 on a synthetic batch to the original `Model`; isolated node leaves the others identical; consistent permutation permutes the outputs; evaluation state unchanged (the audit's runtime checks); cached random walk equal to the recomputed one; the mask-driven mode then switched on and C0.3 asserted (three notions distinct; nodyn/full tensor equality on every non-dynamic tensor; S1/S0 differ only in `xy`; a non-input node whose series is set to a non-zero constant yields identical inputs for every other node and identical masks); scaler statistics from observed-training valid values only (perturbation of hidden nodes' series leaves them identical); graph built from topology only (perturbation of any series leaves A identical).

## 9. Budget rule (before E14-pre)

The original trains for 20 to 200 epochs of **up to** 600 batches each with patience 10 (600 is a maximum per epoch, not a guaranteed length). **U_max = 12 000 is a choice of this protocol**, of the order of the original's shortest trainings, fixed now. The responsible author states the Spark calendar H_cal (hours available for E14) **before** the benchmark; H_cal **includes a reserve of 20 % for extensions and reproductions**; after it, the cost in hours = Σ over the four cell types of n_fits × (12 000 × s_per_update_net + 24 × s_per_validation) / 3600, each cost counted once, with **n_fits = 75 per cell type** for the full grid (300 in total) and **45 per cell type** for the reduced grid (180), each evaluation counted once: if the full-grid cost ≤ 0.8·H_cal, the full grid runs; if not, the uniform reduction of P4R §8 (two configurations, **C1 and C2**, 180 fits) is applied and recorded before the tag, provided its cost ≤ 0.8·H_cal; if the reduced grid also exceeds 0.8·H_cal, the scope is renegotiated collegially (P4R §8) — U_max is **not** lowered below 12 000 to fit the calendar. The decision is taken by `e14.py budget`, which refuses an E14-pre report that is incomplete, whose four C0.1 verdicts are not all passed, that was produced by other code or that does not belong to the reachable E14pre tag (E14pre.md and this specification identical to it, E14.md as at that tag); it is written to `paper4/runs/e14_grid.json`, bound to the report's fingerprint, committed and frozen with the E14 tag; every later command reads the active grid from it and the gate re-verifies the binding and the rule. Checkpoints every 500; adequacy rule and extension to 24 000 as E13B's rule scaled.

## 10. Reading of the contrasts (for E14 draft 3)

Per city, each contrast is the mean over the five splits of the paired per-split value, each per-split value being the mean over the four horizons of the per-horizon MAE ratio (per-horizon aggregation, as E13/E13B). H2.4.c = H2.2.c − H2.3.c is the **difference between the two dynamic benefits**: positive = the benefit of the factor history is larger without coordinates; negative = larger with coordinates; it is not a statement about the benefit or detriment of the coordinates themselves (that is the secondary static contrast at fixed dynamics).
