# MOTION OR3 — code, protocols and frozen records of Paper 4

Paper 4 asks what a road operator buys with traffic sensors. **Part A** asks what the most common urban
sensor, the loop detector, measures of congestion, against independent speed references in Madrid and
Austin. **Part B** asks what instrumented segments tell about segments without a sensor: the models (E11,
E9), the spatial signal in the labels (E12, E12-bis, E12-ter) and placement (E10-geo). The thesis, the
questions and the method are in `protocol/paper4/PROTOCOLLO.md`. The method follows Paper 1 (the
`README.md` at the repository root): signed pre-registrations, frozen records generated by script, one
script that regenerates every number.

This README, the protocols, the frozen records, the code and the paper drafts of Paper 4 are in English.
Three groups of records are kept in Italian, as records, and are summarised in English in
`protocol/paper4/SUMMARIES.en.md`: the Phase 1 records under `protocol/paper4/fase1/`, the executor's
measurement of the causes of items 18–20 (`protocol/paper4/fase2/CAUSE_4A.md`), and the commit messages of
the executor (signatures and freezes). The working notes `paper4/RICOGNIZIONE.md` (Phase 0 survey of the
deliverable), `paper4/DOMANDE.md` (open questions) and `paper4/MODIFICHE_AL_CODICE.md` (changes outside
`paper4/`) are working records, not sources of numbers.

## Reproducing every number

Part B runs in the environment of `models/poetry.lock` (`paper4/ENV.txt`); P4A runs in the environment of the
root `poetry.lock`, which has scikit-learn. From the repository root:

```
PY=<interpreter of models/poetry.lock>
PYA=<interpreter of the root poetry.lock>         # read by main.py as P4A_PYTHON
P4A_PYTHON=$PYA $PY paper4/analysis/main.py                  # complete regeneration
$PY paper4/analysis/main.py --text-only                      # fingerprints and text only (no run folders needed)
P4A_PYTHON=$PYA $PY paper4/analysis/main.py --only E12ter P4A   # selected experiments
```

`main.py` has three steps.

1. **Fingerprints.** Every frozen record, figure and generator is checked against the fingerprints accepted by
   the internal review. For a frozen record with a dated note appended by hand (only when no computed control
   changes, as for P4A), the generated text before the note keeps its original fingerprint and is checked
   separately.
2. **Regeneration.** Each generator runs unchanged on the run folders and writes into a work folder
   (`paper4/analysis/regeneration/<instant>/`, ignored by git), never into `paper4/congelamenti/`. Every number
   of each `*_risultati.json` is compared with the frozen one; each Markdown record is compared line by line,
   with its "Generated by" line and any dated note masked.
3. **Text.** Every number written in `paper4/paper/*.md` must be the rounding of a value in the frozen records
   that the section declares as its sources, a declared design constant, or a declared provenance (listed in the
   report). A match shows that the number exists in the declared sources at that rounding, not that it is the
   right cell.

Training, model evaluation on the cells and the measured timings are inputs: they are not re-run, and their
fingerprints are checked by the generators. The exit code is 0 only if every step passes. Each run writes
`paper4/analysis/reports/<instant>.md`. A complete run also writes `paper4/analysis/CONFRONTO.md`, with the
outcome ("EVERYTHING COINCIDES" or "DIFFERENCES OR ERRORS"), the commit of the code and the fingerprints of the
text files.

The run folders under `paper4/runs/` (per-cell predictions and checkpoints, about 23 GB) are not in the
repository; `paper4/runs/MANIFEST.tsv` lists them. Part A also reads the deliverable's data:
`OR3/data_collection/go-mo/gomo` (Madrid loops), the Traffic4cast speed classes, and the Austin radar file
`radar_completo.json` (2.45 GB), all fingerprinted in `P4A.md`.

## The draft of the paper

```
python3 paper4/manuscript/build.py
```

It converts `paper4/paper/*.md`, in the order of `paper_order.md`, into `paper4/manuscript/main.tex`
(IEEEtran journal class, XeLaTeX, the fonts of Paper 1) and compiles `main.pdf` with Tectonic; the register of
corrections is typeset as the supplement. `main.tex` is generated: the Markdown files are the text of record,
and their numbers are the ones `main.py` checks.

## Protocol, records and corrections

Deviations from a pre-registration are declared, with date and reason, in the pre-registration or in the
frozen record. Defects found during the study, in the deliverable or in the Paper 4 pipeline, are listed in
`protocol/paper4/REGISTRO_CORREZIONI.md` with the correction adopted, its measured effect and its source.
Frozen code is never modified: checks added after a freeze live in new files that import it (for example
`verifica_e12.py`, `verifica_p4a.py`).
